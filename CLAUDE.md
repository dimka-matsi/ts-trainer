# Preflight

Preflight — интерактивный тренажёр для подготовки к фронтенд-собеседованию. Главный экран (хаб) — выбор направления. У каждого направления свой курс, задания, экзамены, флеш-карточки, тренировка ответа вслух и свой стиль. Интерфейс и учебный контент — на русском.

Направления:

- **TypeScript** (`#/ts`): уроки по порядку TypeScript Handbook, песочница с настоящим компилятором, упражнения проверяет компилятор. Пиксельный стиль в синем цвете TS.
- **Браузер** (`#/web`): как устроены сеть и браузер — IP и порты, TCP/UDP, DNS, HTTP (включая устройство cookies), HTTPS и TLS, HTTP-кэш, CDN, устройство браузера, отрисовка, реальное время. Стиль DevTools: карта как вкладка Network, урок — панель с вкладками, схема обмена по шагам и вкладка «Сеть» с водопадом.
- **Безопасность** (`#/sec`): как атакуют и как защищаться — флаги cookies (`HttpOnly`, `Secure`, `SameSite`, сторонние), политика одного источника и CORS, атаки (XSS, CSRF, clickjacking, открытый редирект), заголовки защиты (CSP, SRI, nosniff, COOP и COEP), аутентификация (сессия и JWT, refresh-токены, OAuth, пароли, passkeys, права доступа), эксплуатация (загрузка файлов, секреты во фронтенде, лимит запросов). Опирается на «Браузер». Стиль отчёта сканера уязвимостей: категории с уровнем опасности, уроки — находки со статусом «исправлено», «открыто», «не проверено».
- **Оптимизация** (`#/perf`): как сделать быстрее и как это измерить — измерение (Core Web Vitals, профилирование, бюджеты), сеть и загрузка, сборка и бандл (webpack, Vite, чанки), сервер, рендеринг и интерфейс, React, JS-движок и в конце разбор типовых задач собеседования («сайт тормозит», лента с картинками, медленный старт SPA, тяжёлая таблица). Опирается на «Браузер». Стиль отчёта Lighthouse: карта — категории с круговыми шкалами и уроки-аудиты.
- **React** (`#/react`): всё, что спрашивают о React. Регионы по порядку: компоненты и JSX, состояние в компоненте, хуки и эффекты, рендеринг (reconciliation, Fiber, переходы, Suspense, Activity), Context, Redux и Redux Toolkit, внешние хранилища (Zustand, MobX, Jotai, Effector), серверное состояние (TanStack Query, RTK Query), выбор и архитектура состояния, производительность (Profiler, React Compiler), формы и Actions (React 19), сервер и Server Components, паттерны, тестирование. Каждая страница справочника react.dev привязана к уроку, карточке или пропущена с причиной в `content/react/reference.ts`, verify это проверяет — новые API React добавляют туда же. Код есть: пример в теории (`theory.code`) и код к вопросу (`code` у `quiz`), только для чтения, verify проверяет его синтаксис. Стиль React DevTools: карта — дерево компонентов слева и пропсы выбранного региона справа.
- **JavaScript** (`#/js`): язык и работа со страницей. Регионы: типы и значения, области видимости и замыкания, функции и `this`, объекты и прототипы, массивы и коллекции, асинхронность и event loop, DOM и события, Web API, модули и современный JS, live coding (debounce, throttle, deepClone, deepEqual, flatten, memoize, Promise.all, EventEmitter, curry, retry, пул промисов). Код выполняется по-настоящему: в браузере — в Web Worker (`engine/jsWorker.ts`, запуск через `state/jsRun.ts`), в verify — в Node (`engine/jsRunner.ts`), всегда в строгом режиме, как модуль. Задания «что выведет» (`quiz` с `output: true`) и «напиши код» (`run`) verify проверяет запуском. Стиль консоли DevTools с жёлтым акцентом JS: карта — массив регионов, выведенный в консоль.
- В «Браузере», «Безопасности» и «Оптимизации» **нет JavaScript-кода** ни в теории, ни в заданиях (verify это проверяет). Устройство JS-движка объясняется схемами и словами.
- Граница между направлениями: каждое отвечает на один вопрос. «Браузер» — как это работает (механизмы), «Безопасность» — как атакуют и как защищаться, «Оптимизация» — как ускорить и измерить (приёмы). Границы направлений повторяют ветки дорожной карты собеседования: Сети, Security, Оптимизация. Новую большую тему сначала относят к направлению, а если это другой вопрос — заводят новое направление.
- Node.js и Vue — на хабе как «скоро».

Каждое направление задаёт свои токены через `:root[data-track="…"]` в `styles.css` (`hub`, `ts`, `web`, `sec`, `perf`, `react`, `js`); `App.tsx` ставит атрибут по маршруту.

Учебный план и статус регионов: `docs/curriculum.md`. Новые уроки берём оттуда, по порядку раздела «Порядок дальше».

## Команды

- `npm run dev` — dev-сервер Vite на http://localhost:5180 (порт закреплён в `vite.config.ts`). Нужен Node ≥ 22.12, в `.nvmrc` указан 24.
- `npm run typecheck` — `tsc --noEmit`, строгий режим.
- `npm run verify` — прогоняет ВЕСЬ контент через компилятор (см. ниже). Запускать после любой правки уроков или уровней.
- `npm run build` — typecheck + production-сборка.

Перед тем как считать задачу готовой: `npm run typecheck && npm run verify && npm run build`.

Курсы без кода: `#/<курс>` карта, `#/<курс>/lesson/<id>`, `#/<курс>/exam/<n>`, `#/<курс>/cards`, `#/<курс>/progress`, `#/<курс>/interview`, где курс — `web`, `sec`, `perf`, `react` или `js`. У каждого направления в шапке одинаковый набор: «Карта», «Карточки», «Прогресс», поиск (кнопка и клавиша `/`) и тема. Поиск (`ui/SearchDialog.tsx`) и пробное собеседование (`views/InterviewView.tsx`) общие: данные им передаёт направление (`SearchSource`, `InterviewConfig`).

Курсы на общем движке («Браузер», «Безопасность», «Оптимизация» без кода, «React» с кодом для чтения и «JavaScript» с выполнением кода):


Экзамены и карточки общие для направлений: `ExamView({ cfg })` и `CardsView({ cards, regionNames })`. Ключ экзамена курса — `examBase + регион` (100 у «Браузера», 200 у «Оптимизации», 300 у «Безопасности», 400 у «React», 500 у «JavaScript»). Карточки уроков — `net-lesson-<id>`, `opt-lesson-<id>`, `sec-lesson-<id>`, `react-lesson-<id>` и `jsc-lesson-<id>`. id уроков и карточек уникальны во всех направлениях: прогресс общий.

Компилятор TypeScript (пакет `typescript@5.9.3`, версия закреплена) грузится лениво отдельным чанком ~3.5 МБ. Не импортируй `typescript` статически из клиентского кода — только через `state/engine.tsx`. Внутри один LanguageService; вызовы синхронные и идут по очереди. Код урока может первой строкой включить флаги компилятора — `// @flags: noUncheckedIndexedAccess, strictNullChecks=false` (список разрешённых — `FLAG_NAMES` в `engine.ts`) — и разбиться на несколько файлов строками `// @filename: api.ts`, как в песочнице TypeScript; ошибки и подсказки показываются на строках общего кода. Типы React — настоящие файлы `@types/react` 19 и заглушка вместо `csstype` — подгружаются, только когда код импортирует `react` или использует JSX в файле `.tsx`.

## Как добавить урок

1. Создай `src/content/lessons/<регион>/NN-slug.ts`, экспортируй `lesson: Lesson`. Формат — `src/content/types.ts`.
2. Добавь импорт в `index.ts` региона. Для нового региона с уроками: новая папка, её список в `lessons/index.ts`, регион с `kind: "lessons"` в `regions.ts` на нужном индексе, `region` в уроках = этот индекс. В регионе-сортировщике урок подключается темой с полем `lesson` в `topics`. Достижение за весь регион — `REGION_ACHIEVEMENT` в `state/progress.tsx`.
3. `npm run verify` должен пройти.
4. Сверка с документацией: открой главу Handbook, пройди по её заголовкам и привяжи каждый раздел в `content/handbook.ts` к новому уроку. Раздел без урока — либо тема плана на карте, либо `skip` с причиной.

Правила контента:

- Урок: `q` — вопрос в формулировке собеседования; `answer` — образец ответа вслух на 2–3 предложения; `theory.p` — 3–4 абзаца, короткие предложения; `theory.example` — код, который открывается в песочнице. Ошибки в нём полезны, но каждая строка с ошибкой помечается комментарием `// ошибка`, и verify проверяет, что ошибки ровно там; `keys` — ровно три пункта.
- 2–4 упражнения, разные механики: минимум одно `predict` и одно `code`.
- `predict`: варианты записываются так, как их печатает компилятор в одну строку (`{ a: number; b: string; }`, порядок членов union как у TS). `probe` — имя объявления в `code`. В коде не должно быть ошибок.
- `code`: стартовый код обязан НЕ проходить проверку, `solution` — проходить. `kind: "write"` для «напиши тип/утилиту», `"fix"` для «почини». Скрытые тесты пишутся через `Expect<Equal<A, B>>` и `// @ts-expect-error`. Для задач на написание утилиты запрещай встроенную версию через `forbid: [{ re: "\\bPartial\\b", msg: "Без встроенного Partial" }]`. `runtime` — пары [выражение, ожидаемый JSON], когда важна логика, а не только типы. `must` — фрагменты, которые нельзя удалить (защита от «удалил код — ошибок нет»).
- Все утверждения о поведении TS проверяются компилятором через verify, а не по памяти.
- Флаги сверх `strict`, модули, `.d.ts` и `.tsx` показывают прямо в коде: `// @flags:` первой строкой, `// @filename:` для каждого файла. Проверка `must` не видит комментарии, поэтому флаги в неё не пишут. Уроки «TS и React» начинают код с `// @filename: App.tsx` и импортируют типы из `react` явно.
- Порядок тем: урок использует только то, что пройдено раньше него. Это касается теории, примера, заданий, вариантов ответа, экзамена и карточек региона. `scripts/verify-order.ts` знает, в каком уроке проходят каждую конструкцию (`declare` — b3, union — b5, `keyof` — регион 5…), и роняет verify при нарушении. Если конструкция нужна раньше, её объясняют в том уроке, где она впервые появилась, и переносят там поле `at`. Порядок уроков в регионе задаёт массив в `index.ts` региона, id при перестановке не меняются.
- Термины объясняются при первом появлении простыми словами. Не пишем «рантайм», «эмит», «TS» — пишем «во время работы программы», «создаёт `.js`-файлы», «TypeScript».
- Вопрос «предскажи тип» говорит, где смотреть тип: «Какой тип будет у `r` внутри ветки `if (x != null)`?», «Какой тип TypeScript выведет для переменной `n`?». У `quiz` можно указать `example` — код к объяснению.
- Тексты: русский, простые глаголы, без канцелярита; код и имена типов — в обратных кавычках (их рендерит `Md`).

## Экзамены и флеш-карточки

- Экзамен региона собирается из `predict` и `quiz` его уроков плюс вопросов из `EXAM_ONLY` в `content/exams.ts`. Кнопка экзамена появляется, когда в пуле не меньше 6 вопросов. Для региона-сортировщика вопросы только из `EXAM_ONLY`. Правила те же, что для упражнений урока, verify проверяет каждый вопрос.
- Карточка в `content/flashcards.ts`: стабильный `id` (по нему хранится прогресс, не меняй), `region`, `level` (`junior`, `middle`, `senior`), вопрос `q`, ответ вслух `a` на 2–4 предложения, необязательный `code`. Код карточки компилируется в verify: ошибки допустимы только под `// @ts-expect-error`, доступны `Expect` и `Equal`. Полной DOM-библиотеки в движке нет — только минимальные объявления из `lib.ts` и `global.d.ts` типов React. Если у урока нет отдельного примера для карточки, она берёт пример из теории.
- Если `q` карточки совпадает с `q` темы в `regions.ts`, диалог темы на карте показывает ответ карточки как образец.
- Новый урок сам даёт карточку (`lesson-<id>`), дублировать его вопрос не нужно.

## Как добавить урок курса на общем движке («Браузер», «Безопасность», «Оптимизация», «React», «JavaScript»)

Файл `src/content/<курс>/lessons/<регион>/NN-slug.ts`, экспорт `lesson: WebLesson`, импорт в `index.ts` папки региона. Новый регион — новая папка и её `lessons` в `REGION_LESSONS` в `content/<курс>/index.ts` на индексе региона. Новый курс — папка с `index.ts` через `makeCourse`, запись в `content/courses.ts` и `COURSE_IDS` в `state/route.ts`, своя карта и стиль `data-track`. id уроков уникальны и не совпадают с id уроков TypeScript (прогресс общий, verify это проверяет). В регионе нужно не меньше 6 вопросов `quiz` для экзамена. Правила текста те же, что у уроков TS, плюс:

- У урока есть разбор: `theory.flow` (схема обмена: участники и шаги-стрелки, `lost` — потерянный пакет) и/или `theory.requests` (запросы для вкладки «Сеть»: HTTP-сообщения и фазы тайминга). В курсе с запуском кода (`runnable`) разбором может быть сам пример `theory.code` — у него кнопка «Запустить».
- Задания: `quiz`, `order` (шаги в правильном порядке, интерфейс перемешает), `match` (пары, правые части не повторяются), `sort` (пункты по группам), а в курсе с запуском — `run`. 2–4 задания, минимум двух видов. В экзамен идут только `quiz`, поэтому вопрос не ссылается на вкладку урока.
- verify проверяет: коды ответа и их фразы по RFC 9110, стартовые строки, `Host` в HTTP/1.1, отсутствие тела у 304 и 204, `SameSite=None` только с `Secure`, порядок фаз (Очередь, DNS, TCP, TLS, Ожидание ответа, Загрузка), TLS только с новым TCP.
- В курсах без кода никакого JavaScript: `=>`, `const`, `console.` и подобное роняют verify. В курсах с кодом (`withCode`: «React» и «JavaScript») код пишут только в `theory.code`, `code` и `example` у `quiz`, `code` и `solution` у `run` и `code` у карточки; он должен быть синтаксически верным TSX — verify разбирает его компилятором, но типы не проверяет (библиотек вроде Redux в проекте нет), поэтому факты об API сверяют с документацией.
- Курс с запуском кода («JavaScript»):
  - `quiz` с `output: true` — «что выведет»: варианты — вывод консоли, строки через `\n`. verify выполняет `code`, верный вариант должен совпасть с настоящим выводом, остальные — нет. Формат вывода задаёт `show()` в `jsRunner.ts`: строки без кавычек, вложенные строки в двойных кавычках, объекты `{ a: 1 }`, массивы `[1, "x"]`, необработанная ошибка — `Uncaught ИмяОшибки`. Порядок, зависящий от лишних шагов цепочки промисов, переписывают через `await`, чтобы вопрос проверял одну идею.
  - `run` — «напиши код»: `code` (стартовый код обязан провалить хотя бы одну проверку), `tests` — пары [выражение, ожидаемый JSON] (можно `await` и `sleep(мс)`), `solution` (проходит все), `hint`, `forbid`. Стартовый код не должен зависать: в verify синхронный бесконечный цикл не прервать.
  - Пример теории выполняется без необработанных ошибок; намеренную ошибку помечают `// ошибка`. Код со страницей, сетью или модулями (`document`, `window`, `localStorage`, `fetch(`, `import`…, см. `needsPage`) не выполняется — его показывают без кнопки, а задания к нему — обычные `quiz`, `order`, `match`, `sort`.
- Порядок тем: список «понятие → урок» в `verify-web.ts` (TCP, UDP, DNS — net2, рукопожатие — net3, cookie — http1, CORS — cors1…). Раньше своего урока понятие не упоминается в тексте, схеме и заданиях. HTTP-сообщения вкладки «Сеть» — снимок настоящего обмена, их заголовки порядок тем не проверяет.
- HTTP-сообщения собирай через `msg()` из `content/course/http.ts`: он сам ставит `Content-Type` и `Content-Length`. verify сверяет `Content-Length` с телом, проверяет префиксы cookie `__Host-` и `__Secure-`.
- Факты о протоколах сверяются с RFC и MDN, а не по памяти.

## Как добавить уровень сортировщика

Уровень описывается данными в `content/sorter/levels.ts`: члены union (`members`), шарики с реальными значениями, выходы (`exits`, `final`) и условия (`checks`). У условия есть `run` (рантайм) и `n` — как оно сужает каждый член: `yes`, `no` или `both`. Ошибку компиляции условия задаёт `error`. Уровень-босс (`boss: true`) вместо `n` использует `tx` — переход состояния `BossState`. Добавь эталонное решение в `solutions.ts`, иначе verify упадёт.

Модель сортировщика упрощённая и написана руками. Тексты ошибок и коды (TS2345, TS2367, TS18047…) должны совпадать с настоящим компилятором — сверяй в песочнице.

## Стиль кода

- TypeScript strict, без `any` в клиентском коде (в `lib.ts` декларации окружения с `any` допустимы).
- Функциональные компоненты, состояние — хуки и контексты из `state/`. Внешних UI-библиотек нет, стили — `src/styles.css` с токенами в `:root` и тёмной темой через `prefers-color-scheme` и `data-theme`.
- Компоненты не знают про localStorage напрямую — только через `useProgress`.
- Доступ к темам решает путь обучения `state/path.ts`: регионы по порядку карты (кроме «скоро»), в регионе-сортировщике сначала уровни, потом уроки. Шаг открыт, если он пройден или пройдены все шаги до него. Экзамен региона открывается после всех его тем. Флеш-карточки открыты всегда. Закрытые урок, уровень и экзамен по прямой ссылке показывают `LockedView`.
- Прогресс хранится в двух местах: localStorage и файл `.local/progress.json` (в `.gitignore`). Файл пишет плагин `scripts/progress-file.ts` через `GET`/`PUT /__progress` в `npm run dev` и `npm run preview`. При старте побеждает копия с более новым `updatedAt`. Сервер не принимает копию старее той, что в файле (ответ 409 с актуальной версией), а вкладка при возвращении на неё и по событию `storage` подтягивает более новый прогресс. Так долго открытая вкладка не затрёт свежий прогресс. Без сервера (статическая сборка) остаётся только localStorage.
- Тестовый режим: адрес с `?test` (`http://localhost:5180/?test#/web`) хранит прогресс под отдельным ключом `ts-trainer-test` и не пишет в файл. Проверки, которым нужны открытые или пройденные уроки, делают только так — настоящий прогресс не трогают.
- Уважай `prefers-reduced-motion` (анимация сортировщика уже проверяет).

## Экраны

Хаб: сверху сам печатается и сменяется вопрос с собеседования из карточек всех направлений (`views/HubQuestion.tsx`, пауза при наведении, «Показать ответ»), ниже карточки направлений — первой и шире та, где пройдено больше всего, у каждой следующий урок. Кнопка возврата на хаб в шапке любого направления — `ui/HubButton.tsx`: четыре плитки цветов направлений, текущая горит.

Карта (регионы сворачиваются, текущая тема подсвечена), урок (внизу закреплённая полоса с разделами и прогрессом упражнений), уровень сортировщика, экзамен, флеш-карточки (интервальное повторение: 1, 3, 7, 16, 35 дней), пробное собеседование `#/interview` (вопросы только из пройденного, минута на ответ), прогресс `#/progress` (регионы, экзамены, достижения). Поиск открывается кнопкой в шапке и клавишей `/`.

Редактор (`ui/CodeEditor.tsx`) — прозрачная textarea поверх подсветки. Наведение показывает текст ошибки или тип (`engine.quickInfo`), ввод и Ctrl+Пробел — автодополнение (`engine.completions`).

Шрифты: пиксельный Pixelify Sans только для логотипа и крупных заголовков, остальной текст и кнопки — Onest. Контраст текста — не ниже WCAG AA (4,5:1) в обеих темах.
